A layout update for the desktop app, plus fixes to how local and release builds are packaged.

```sh
brew upgrade --cask verda
```

The upgrade quits the running app first (the bot gets up to 20 seconds to finish its requests,
and the rest resume on the next start) and reopens it. Config and run history in `~/.verda` are
untouched.

## New layout

- Sections move to an icon rail on the left: Overview and Bot at the top, Settings at the bottom.
- Run search sits in the top bar. Cmd+K focuses it from any screen, Esc clears it, and typing on
  the Bot or Settings screen jumps to the run list.
- The run list shows beside the overview and run details, while the Bot and Settings screens use the
  full window width.
- Drag the edge of the run list to resize it (260 to 560 pixels); double-click the edge to restore
  the default. The width is remembered, and the status filter turns into a menu when the list is
  too narrow for its five buttons.
- Theme (System, Light, Dark) moves from the status bar into the App section of Settings.
- The title bar no longer repeats the app name.

## Fixes

- A long run history folder path no longer pushes the Settings layout out of shape.
- Local builds (`pnpm package:mac`) keep only the release zip, so Spotlight and Launchpad list just
  the installed Verda. `pnpm install:mac` installs from that zip and will not replace a Verda
  installed with Homebrew.
- The release workflow updates the Homebrew tap again; in v0.1.0 that step failed and the cask was
  published by hand.

## For development

- Runs from the repository (`pnpm desktop`, `pnpm desktop:dev`) start as "Verda Dev", next to an
  installed Verda, with a DEV-tagged Dock icon and "Dev" in the menu bar and the top bar.
